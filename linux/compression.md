# 为什么 18K 的文件能压到 101 字节，48 字节的却压不动？

> 一次 `gzip` 对比实验，和它暴露出的一个常见误解

## 起因

同一句话，我造了两个文件：

- 小的：`hello` 重复 8 次，**48 字节**
- 大的：`hello` 重复 1000 行，**18 K**

分别压缩：

```bash
$ gzip -k test.txt && gzip -k big.txt
$ ls -lh test.txt* big.txt*
-rw-r--r-- 1 user user   48 test.txt
-rw-r--r-- 1 user user   39 test.txt.gz      ← 只省了 19%
-rw-r--r-- 1 user user  18K big.txt
-rw-r--r-- 1 user user  101 big.txt.gz       ← 省了 99.4%
```

**大文件压到原来的 1/178，小文件几乎压不动。**

## 一个反直觉的事实

**压缩的效果不取决于"文件类型"，取决于「重复度」。**

很多人以为"文本能压、图片不能压"。**这说法只对了一半** —— 真正的原因是：

| 数据 | 重复度高吗 | 能压吗 |
|---|---|---|
| 纯文本（同一句话反复） | 极高 | ✅ 压得极狠 |
| 代码、日志 | 高 | ✅ 压得好 |
| JPEG / MP3 / MP4 | 已经压过了 | ❌ 几乎压不动，甚至变大 |
| 加密后的数据 | 看起来是随机 | ❌ 压不动 |

**⚠️ 图片音乐压不动，不是"因为它是图片"，是因为「它已经被压过一次了」。**
里面的重复早就被去掉了，剩下的接近随机数据 —— **没有重复可压。**

## 原理

### 压缩在干什么

**把重复的内容换成"代号"。**

```
原文：  hello hello hello hello hello hello
压缩：  (hello) × 6
```

重复越多，代号省下的空间越多。**18K 的 `hello` 重复，几乎全被换成了"重复 N 次"这一个记号。**

### 那 48 字节为什么压不动

**因为压缩文件本身要带一段"管理信息"（元数据 / 文件头）：**

- 原文件名
- 时间戳
- 压缩方法标记
- 校验值

**这段开销是固定大小的。文件小的时候，它占比极高。**

用箱子打比方：

> 把一本 1000 页的书塞进箱子 —— 箱子本身才占几克，划算。
> 把一张纸塞进同一个箱子 —— **箱子比纸还重。**

**→ 一句话：压缩效果 = 重复度 − 元数据开销。**

## 先分清三件事

这三个概念经常被混成一个：

| 动作 | 工具 | 效果 |
|---|---|---|
| **压缩** | `gzip` | **体积变小** |
| **打包** | `tar` | **体积几乎不变**（把多个文件串成一个） |
| **解压 / 解包** | `gunzip` / `tar -x` | 还原 |

**⚠️ 关键：`gzip` 一次只能压一个文件。**

所以"压一堆文件"必须两步：

```
100 个文件 → [tar 打包] → 1 个 .tar → [gzip 压缩] → 1 个 .tar.gz
```

**→ 这就是为什么 `.tar.gz` 有两个后缀 —— 它是两步的产物，不是"一种格式"。**

## `gzip` 的一个坑：原文件会消失

```bash
$ gzip 文件名          # 压缩 —— 原文件被删掉，原地多一个 文件名.gz
$ gzip -k 文件名       # k = keep，保留原文件
$ gzip -d 文件.gz      # d = decompress，解压
```

**为什么默认删掉**：压缩完还留原文件，等于占两份空间 —— 那不叫压缩。

**想保留就加 `-k`。**

## `tar` 的字母是六个独立功能，不是一个词

`-zxvf` 看起来像密码，其实拆开就是六个缩写：

| 字母 | 全称 | 干什么 |
|---|---|---|
| **`-c`** | **Create** | **创建**包（和 `-x` 对立） |
| **`-x`** | **eXtract** | **解**包（和 `-c` 对立） |
| **`-t`** | lis**t** | **只列出内容，不解压** |
| **`-z`** | **gzip** | 顺便调用 gzip（可选） |
| **`-v`** | **verbose** | 把处理的文件都打出来 |
| **`-f`** | **file** | **后面跟文件名**（基本必须） |

**⚠️ `c` 和 `x` 互斥** —— 不能同时"创建"和"解压"。

**⭐ 记法：`-czvf` 和 `-xzvf` 只差中间一个字母。记住这一对，整组就记住了。**

```bash
tar -czvf 包.tar.gz 目录/     # 打包 + 压缩
tar -xzvf 包.tar.gz           # 解压 + 解包
tar -tvf  包.tar              # 只看内容（不解压）
tar -tzvf 包.tar.gz           # 只看内容（压缩包）
```

## `.zip` 和 `.tar.gz` 是两种东西

| | `.zip` | `.tar.gz` |
|---|---|---|
| 解压工具 | `unzip` | `tar -xzvf` |
| 打包 + 压缩 | **一步完成** | **两步** |
| 来源 | **Windows / DOS 世界** | **Unix / Linux 世界** |

**⚠️ `unzip` 解不了 `.tar.gz`**，会报：

```
End-of-central-directory signature not found.
```

**因为它们是两种完全不同的格式。**

**为什么会有两种**：Unix 哲学是"一个工具只干一件事" ——
`tar` 只管打包，`gzip` 只管压缩，**需要组合就串起来用**。
Windows 那边更倾向于"一个工具全包了"。

**→ 这是历史选择，不是谁比谁先进。但你得知道两边的工具不能混用。**

## 为什么这事在安全里重要

**1. `tar -t` 是"先看再解"的技术基础**

`-t` 只读包里的**目录信息**，**不会把文件内容写到磁盘上**。

**→ 所以 `tar -tvf 别人的包` 是安全的。不是靠自律，是它真的不写文件。**

**2. 解压别人的包是一个危险动作**

压缩包里**自己写着文件要放到哪**。包里如果写了 `../`，解压时就会往目录外写。

**→ 详见另一篇：路径穿越（tar traversal / zip slip）。**

**3. 压缩也能用来藏东西**

恶意文件压缩后，静态扫描工具可能扫不出来（因为内容已经不是明文了）。
**但解压之后它就在磁盘上了。**

**→ 所以"扫压缩包"和"扫文件"是两件事，不能互相替代。**

## 一句话总结

> **压缩效果取决于重复度，不取决于文件类型 —— 图片压不动是因为它已经被压过了。**
> **文件小的时候，压缩文件的"管理信息"开销可能比省下的空间还大。**
> **`gzip` 只管压缩，`tar` 只管打包，所以 `.tar.gz` 是两步的产物。**
> **`-t` 只读不写，所以"解压前先看"是安全的。**

## 命令速查

| 我想 | 命令 |
|---|---|
| 压一个文件 | `gzip 文件`（原文件消失）/ `gzip -k 文件`（保留） |
| 解一个 `.gz` | `gzip -d 文件.gz` / `gunzip 文件.gz` |
| 打包一个目录 | `tar -cvf 包.tar 目录/` |
| 打包 + 压缩 | `tar -czvf 包.tar.gz 目录/` |
| 解包 | `tar -xvf 包.tar` |
| 解压 + 解包 | `tar -xzvf 包.tar.gz` |
| **看包里有什么** | `tar -tvf 包.tar` / `tar -tzvf 包.tar.gz` |
| 解 `.zip` | `unzip 文件.zip` |
| 看 zip 里有什么 | `unzip -l 文件.zip` |
| 解到指定目录 | `unzip -d 目标目录 文件.zip` |

**⚠️ 一个易混点：`-k` 在 `gzip` 和 `tar` 里意思不同**

| 命令 | `-k` 的意思 |
|---|---|
| `gzip -k` | **保留原文件** |
| `tar -k` | **解压时不覆盖已有文件** |

**要防止 `tar` 覆盖，用 `tar -xzvkf`。**
