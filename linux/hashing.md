# 为什么 MD5 不能用来存密码？

> 从 `md5sum` 这条命令说起 —— 一个"算得太快"引发的灾难

## 起因

下载了一个工具，官网旁边写着一行校验值：

```
md5: 3f2a9c8b1d4e5f6a7b8c9d0e1f2a3b4c
```

**这行字符是干什么的？** 为什么下载页要放它？

于是去学了一下 `md5sum`，然后撞到一个更值得写的问题：**这东西既然能"验证文件"，那能不能拿来存密码？**

答案是**不能**。而且理由和直觉相反。

## 一个反直觉的事实

**哈希"不可逆"，但这不等于"安全"。**

大多数人对哈希的第一印象是："算出来的东西推不回去，那肯定很安全吧？"

**错。** 安全性取决于**两个**维度，不只是"能不能推回去"：

| 维度 | 要求 |
|---|---|
| 单向性 | 不能从结果推出原文 |
| **速度** | **必须足够慢** |

**⚠️ 而 MD5 的问题恰恰出在第二个：它太快了。**

一秒能算**几十亿**次。这对"校验文件"是优点，对"存密码"是致命缺点。

**同一个工具，两个用途，需求完全相反。**

## 哈希是什么

先建个模型。**哈希 = 指纹。**

```
输入  →  [哈希函数]  →  一串固定长度的字符
"hello"              →  b1946ac92492d2347c6235b4d2611184
```

三个性质：

| # | 性质 | 意思 |
|---|---|---|
| 1 | **定长** | 不管输入 1 字节还是 10 GB，输出长度一样（MD5 = 32 字符，SHA-256 = 64 字符） |
| 2 | **雪崩** | 输入改一个字符，输出**面目全非** |
| 3 | **单向** | 从输出推不回输入 |

### 雪崩效应实测

只改最后一个字母（`o` → `p`）：

```bash
$ echo "hello" | md5sum
b1946ac92492d2347c6235b4d2611184  -

$ echo "hellp" | md5sum
7bd75e0741818d4e6020b0250e52dd46  -
```

**32 位里 32 位全都不一样。**

注意它不是"随机"——是**确定性的**：

- `hello` 永远算出 `b1946ac9...`
- `hellp` 永远算出 `7bd75e07...`

变的是"看起来毫无规律"。**这是设计出来的，不是缺陷。**

**为什么必须这样**：如果改一个字母只差一位，攻击者就能一点点试、慢慢逼近原文。**雪崩让"猜"变得不可能。**

## 先划清界限：它不是压缩，也不是加密

这三个概念太容易混了，一次分清：

| 技术 | 可逆吗 | 例子 |
|---|---|---|
| **压缩** | ✅ 可逆 | `.gz` → 原文 |
| **编码**（base64） | ✅ 可逆 | 解码回原文 |
| **哈希** | ❌ **不可逆** | 只能验证，不能还原 |

**哈希只干一件事：当指纹用。**

## 为什么不能存密码

假设某个网站用 MD5 存密码。数据库泄露之后，攻击者拿到的是：

```
用户A  → 5f4dcc3b5aa765d61d8327deb882cf99
```

### 问题 1：彩虹表

**有人提前把常见字符串的哈希全算好了。**

```
hello    → b1946ac9...
password → 5f4dcc3b...
123456   → e10adc39...
（几亿条）
```

**→ 把哈希贴进去，直接查表得出原文。**

⚠️ 这不是"破解了算法"，是"有人提前算过"。**哈希算法再强，也拦不住一张预先算好的表。**

### 问题 2：算得太快

**MD5 一秒能试几十亿个密码。** 就算没有彩虹表，暴力枚举也扛不住。

### 问题 3：已经找到碰撞

**碰撞 = 两个不同的输入，算出同一个哈希。**

```
"abc"  →  哈希 X
"xyz"  →  哈希 X      ← 这就是碰撞
```

MD5 的碰撞在 2004 年就被实际构造出来了。**一个"可以被伪造指纹"的指纹，不能用来证明任何事。**

### ⚠️ 更反直觉的：SHA-256 也不能存密码

**因为它也"太快了"。**

| 用途 | 要快还是要慢 | 为什么 |
|---|---|---|
| 校验文件 | **要快** | 几十 GB 的文件要秒级出结果 |
| **存密码** | **要慢** | **让暴力猜测变贵** |

**→ 所以存密码要用「故意很慢」的算法：`bcrypt` / `scrypt` / `argon2`。**

（另一种思路是把快速哈希**反复迭代**几万次，人为拖慢 —— 这就是 `PBKDF2`。它是"把快哈希变慢"的过渡方案，新系统一般直接上 `argon2`。）

**→ 这也解释了 `/etc/shadow` 里为什么既不是明文，也不是 MD5。**

## 解法：加盐（salt）

**光换算法还不够。** 还有个问题：

如果全班 30 个人都用 `password` 当密码，数据库里就是 30 条**一模一样**的哈希。

**两个后果，第二个更狠：**

| # | 后果 |
|---|---|
| 1 | 破解一个 = 破解全部（不用算 30 次） |
| 2 | **甚至不用破解** —— 数一数就知道"这 30 个人用同一个密码" |

第 2 条才是关键：攻击者**根本不需要知道密码是什么**，就知道**哪些账号是同一把钥匙**。挑最弱的那个突破就行。

### 解法：给每个人加一段随机字符串

```
用户A：  password + "x7k2"  →  aaa111...
用户B：  password + "9p4m"  →  bbb222...
用户C：  password + "z1q8"  →  ccc333...
              ↑
        这叫 salt（盐），每人一个，随机
```

实测（同一句 `password`，不同的盐）：

```bash
$ echo -n "passwordAAA" | md5sum
d5d859b7de2e1db6eb65197eed1d8fb6  -

$ echo -n "passwordBBB" | md5sum
58fa3aabc0ee3e2bad0bc8053446c450  -

$ echo -n "password" | md5sum
5f4dcc3b5aa765d61d8327deb882cf99  -
```

**三个完全不同的哈希。**

**⚠️ 盐不需要保密** —— 它和哈希**一起存在数据库里**。它的作用不是"藏起来"，而是**让每个人的指纹都不一样**。

| 问题 | 加盐后 |
|---|---|
| 同样的密码，哈希一样吗？ | 不一样了 |
| 能看出谁跟谁用同一个密码吗？ | 不能了 |
| 彩虹表还有用吗？ | 没用了（表里没有 `passwordx7k2` 这一项） |

### ⚠️ 但盐不是万能的

**盐不增加密码本身的强度。**

```
密码 "123456" + 盐 "x7k2"
      ↓
哈希看起来很复杂，但密码还是 "123456"
      ↓
攻击者针对这一个人猛猜 → 猜 "123456" + 盐 → 还是能破
```

| 盐能防 | 盐不能防 |
|---|---|
| **一次破所有人**（批量、查表） | **针对单个人的暴力破解** |

**→ 所以"用强密码"这条老话，加了盐之后依然成立。**

### 别混：盐 ≠ 碰撞

| 概念 | 意思 |
|---|---|
| **盐（salt）** | 哈希**之前**加的随机字符串，让相同密码产生不同哈希 |
| **碰撞（collision）** | 两个**不同输入**算出**同一个哈希**（算法本身的性质） |

**两件事。盐治的是"查表"，不是"碰撞"。**

## 那哈希能拿来干什么

**回到最开始那个问题：下载页那行校验值。**

```
官方发布：  setup.exe
官方公布：  md5sum = 3f2a...
        ↓
你下载完，自己算一遍
        ↓
一样 → 没被动过 ✅
不一样 → 被换过了 🔴 别运行
```

```bash
$ sha256sum setup.exe
$ sha256sum -c setup.exe.sha256
setup.exe: OK
```

**⚠️ 实际用的时候优先选 `sha256sum`，不要用 `md5sum`** —— MD5 已经可以被伪造。

**不过严格说**：校验值如果和文件放在同一个网站上，攻击者改了文件也能顺手改校验值。**真正可信的校验值要来自独立渠道**（官方公告、签名邮件、另一个站点）。

## 为什么这事在安全里重要

**1. 这是一个通用习惯的第三种形式**

| 场景 | 怎么防 |
|---|---|
| 别人给一条**命令** | 先 `man`，看懂再敲 |
| 别人给一个**压缩包** | 先 `tar -tzvf`，看路径再解 |
| **别人给一个文件** | **先算哈希，对得上再运行** |

**→ 这不是三个技巧，是一个习惯：别人给的东西，先验证。**

**2. 看到"用了 MD5 存密码"就知道这站有问题**

一个网站如果还在用 MD5 存密码，说明它的安全实践停留在 2000 年代。
**这条判据不需要读它的代码 —— 从一次数据泄露的格式就能看出来。**

## 一句话总结

> **哈希不可逆，但不等于安全 —— 安全性还取决于"算得够不够慢"。**
> **MD5 太快，且已被证明可碰撞，所以不能存密码。**
> **SHA-256 够强，但也太快，同样不能直接存密码。**
> **存密码要用"故意很慢"的算法（bcrypt / argon2），并且必须加盐。**
> **盐让相同密码产生不同哈希，但它挡不住针对一个人的暴力破解。**

## 命令速查

| 命令 | 作用 |
|---|---|
| `md5sum 文件` | 算 MD5（32 字符，**已不推荐用于安全用途**） |
| `sha256sum 文件` | 算 SHA-256（64 字符，**校验用这个**） |
| `sha256sum -c 校验文件` | 校验（输出 `OK` / `FAILED`） |
| `echo -n "字符串" \| md5sum` | 算一个字符串（**`-n` = 不加换行**，加了就是另一个哈希） |
| `md5sum a.txt b.txt` | 一次算多个，直接对比 |
| `md5sum *.txt > 校验.md5` | 批量生成校验文件 |

**输出末尾的 `-`**：表示内容来自管道，没有文件名。用文件时会显示文件名。

| 哈希算法 | 现在能用吗 | 用途 |
|---|---|---|
| MD5（1992） | ❌ 已破 | 淘汰中 |
| SHA-1（1995） | ❌ 2017 年被破 | 淘汰中 |
| **SHA-256 / SHA-512** | ✅ | 校验文件、数字签名 |
| **bcrypt / argon2** | ✅ | **存密码**（故意慢） |

**记不住名字没关系，记住判据就行：**

> **这个哈希是"快"还是"慢"？**
> **校验文件 → 用快的。存密码 → 用慢的。**
