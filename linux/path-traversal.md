# 解压一个压缩包，文件为什么会跑到别的目录？

> 亲手做一次路径穿越（tar traversal / zip slip）

## 起因

解压一个压缩包时，文件应该出现在**我指定的目录**里。

**但如果压缩包里自己写着"我要放到上一级目录"，会怎么样？**

我造了一个包试了一下。**结果它真的跑出去了。**

## 一个反直觉的事实

**压缩包里"自己写着"每个文件要放到哪 —— 你不检查，解压工具就照做。**

更反直觉的是：**`tar` 完全不拦，`unzip` 会拦。**

| | 包里写了 `../` 时 |
|---|---|
| **`tar`** | **照做**（照写不误） |
| **`unzip`** | **会剥掉 `../`**，拒绝对路径 |

**⚠️ 同一类攻击，两个工具两种态度。** 所以不能"以为都一样"，**每个工具要单独确认。**

这也导致它有两个名字：

| 名字 | 载体 |
|---|---|
| **tar traversal** | `.tar` / `.tar.gz` |
| **zip slip** | `.zip` |

## 先搞清 `..` 和 `/`

这两个符号容易混：

| 写法 | 意思 | 例子 |
|---|---|---|
| **`..`** | **上一级（父目录）** | 从 `/tmp/trap` 上一级 → `/tmp` |
| **`/`** | **根目录（最顶层）** | 整个文件系统的顶 |
| `.` | 当前目录 | |

**⚠️ `../` 是"退一级"，不是"去根目录"。**

而且 **`..` 可以叠加**：

```
../                    → 退 1 级
../../                 → 退 2 级
../../../../../../etc/ → 一直退到根，然后进 /etc
```

**⚠️ `/` 是顶，退到根之后再多的 `..` 也无效。**

**→ 所以攻击者会写"很多个 `..`"：不是为了精确，是为了「保证退到顶」。**

## 完整实验（可复现）

### ① 建实验场

```bash
mkdir -p /tmp/trap/innocent && cd /tmp/trap
```

`mkdir -p` 的 `-p` = parents，父目录不存在也自动建。

### ② 造一个"撒谎"的包

```bash
echo "我是恶意内容" > payload.txt
tar -czf evil.tar.gz --transform 's|^payload.txt|../HACKED.txt|' payload.txt
```

| 部分 | 意思 |
|---|---|
| **`--transform 's\|A\|B\|'`** | **篡改包里的路径**：把 A 换成 B |
| `^payload.txt` | `^` = 开头，匹配"以 payload.txt 开头" |
| `../HACKED.txt` | 换成这个 —— **退一级** |

**⚠️ 这就是模拟攻击者干的事：文件真名叫 `payload.txt`，但在包里撒谎写成 `../HACKED.txt`。**

（`s|A|B|` 和 `sed` 是同一套语法：把 A 换成 B。）

### ③ 先看，不解压

```bash
$ tar -tzvf evil.tar.gz
-rw-r--r-- user/user  15 2026-10-01 15:33 ../HACKED.txt
```

**⚠️ 输出里的文件名是 `../HACKED.txt` —— 这就是"包里撒谎"的铁证。**

**这一步就是防御本身。真实场景到这就该停了。**

### ④ 解压验证

```bash
cd /tmp/trap/innocent && tar -xzvf ../evil.tar.gz && ls -la /tmp/trap/
```

**结果：文件真的落到了上一级（`trap/`），不是当前目录（`innocent/`）。**

`-xzvf` 一点没拦。

### ⑤ 清理

```bash
rm -rf /tmp/trap
```

**⚠️ 这个 `rm -rf` 用得对** —— 对象是**自己刚建的实验目录**，路径明确、在 `/tmp` 里。
这和"不确定的 `rm -rf /*`"是两回事。

## 危险到底在哪

**很多人第一反应是："不就是换个地方放文件吗？"**

**不是。危险分三层：**

| 层次 | 危险在哪 |
|---|---|
| **① 位置** | 不是你选的地方 → 你以为解压到"下载文件夹"，其实写进了 `~/.ssh/` |
| **② 性质** | **覆盖** —— 不是"多一个文件"，是**把你原有的文件换成他的** |
| **③ 目标** | 挑"**会自动执行**"的位置（`.ssh` / `.bashrc` / `cron` / `systemd`） |

**⭐ 第三层才是真正的杀招：他写的文件，你的系统会主动运行。**

### 真实攻击长什么样

| 包里写的路径 | 实际效果 |
|---|---|
| `../HACKED.txt` | 退一级（实验里这个，无害） |
| `../../.ssh/authorized_keys` | **替换你的 SSH 公钥 → 对方能直接登录你的机器** |
| `../../../etc/cron.d/backdoor` | **塞进系统定时任务 → 每隔几分钟自动跑** |
| `../../../../../../root/.bashrc` | **下次开终端就执行对方代码**（若权限够） |
| `/etc/passwd` | **绝对路径** —— 直接覆盖（连 `..` 都不用） |

**⭐ 一句话：**
> **危险的不是"换个地方"，是"换到你能被控制的地方"。**
> **`../` 那一步本身不危险 —— 危险的是它让攻击者跳出了你划定的边界。**

### 为什么"覆盖"这么致命

`tar -x` 遇到同名文件**直接覆盖，不问你**。

（`unzip` 反而会问你要不要覆盖。）

**→ 路径穿越的伤害 = 两件事叠加：**

```
① 写到目录外（..）
        +
② 覆盖同名文件（不问）
        ↓
攻击者把 .ssh/authorized_keys 换成自己的
        ↓
他拿到了你机器的登录权限
```

**单靠①不够狠 —— 真正的杀招是②：它替换掉一个你本来就信任的文件。**

## 为什么 `tar` 不拦

**因为 `tar` 的职责是"还原"，不是"审查"。**

**Unix 的设计哲学（1970 年代）：**

> **"工具只管干活，不管判断。判断是人的事。"**

| 工具 | 它的逻辑 |
|---|---|
| `rm` | 你让我删，我就删（**包括系统文件，不问你**） |
| `tar -x` | 你让我还原这个路径，我就还原 |
| `dd` | 你让我写扇区，我就写 |

**⚠️ 这不是 bug，是设计。正因为是设计，它不会"修"，只能你自己防。**

**⭐ 最反直觉的点：**
> **工具越"听话"，被利用时越危险。**
> **`tar` 不是受害者 —— 它是亲手执行的执行者。**

## 怎么防

### 拿到别人的包，先看内容

| 格式 | 命令 |
|---|---|
| `.tar` | **`tar -tvf 包.tar`** |
| `.tar.gz` | **`tar -tzvf 包.tar.gz`** |
| `.zip` | **`unzip -l 包.zip`** |

**记法：`tar` 用 `t`（lis**t**），`unzip` 用 `l`（lis**t**）。**

### 判断标准

| 看到的路径 | 处理 |
|---|---|
| 相对路径、正常目录名 | ✅ 可以解 |
| **`../` 开头** | 🔴 **扔了** |
| **`/` 开头的绝对路径** | 🔴 **扔了** |

### 更强的做法：解压到隔离目录

```bash
mkdir /tmp/sandbox && tar -xzvf 包.tar.gz -C /tmp/sandbox
```

`-C 目录` = 解压前先 `cd` 到该目录。

**⚠️ 但这不是万能的** —— `..` 多退几级照样能出去。**`-C` 只是减少损失，不是防御。**

**→ 真正的防御还是第一步：看。**

## 为什么这事在安全里重要

**1. 它和命令注入是同一个根因**

| | 攻击点 | 本质 |
|---|---|---|
| **命令注入** | 用户输入的**字符串**被当命令执行 | **输入没有被验证** |
| **路径穿越** | 压缩包里的**文件名**被当路径执行 | **输入没有被验证** |

**⚠️ "文件名也是输入"这一点很反直觉，但它就是。**

**→ 防御原则一样：不信任任何外部来的东西，先验证再用。**

**2. 这是一个通用习惯的又一种形式**

| 场景 | 怎么防 |
|---|---|
| 别人给一条**命令** | 先 `man`，看懂再敲 |
| **别人给一个压缩包** | **先 `tar -tzvf`，看路径再解** |
| 别人给一个**文件** | 先算哈希，对得上再运行 |

**→ 不是三个技巧，是一个习惯。**

**3. ⚠️ 沙箱实验 vs 真实场景，处理完全不同**

| 场景 | 该怎么做 |
|---|---|
| **真实拿到的可疑包** | **看完 `-tzvf` 就扔，不解压** |
| **沙箱实验（像本文）** | 解压，为了验证原理 |

**本文之所以敢解压，是因为包是在 `/tmp` 里自己造的、内容是自己写的、跑完就删。**
**换成别人的包，看完那一步就停。**

## 一句话总结

> **压缩包里自己写着文件要放到哪 —— 你不检查，解压工具就照做。**
> **`tar` 不拦 `../`，也不拦绝对路径；`unzip` 会剥掉 `../`。**
> **危险的不是"换个地方"，是"换到你能被控制的地方"。**
> **防御只有一条：解压前先 `-tvf` 看内容。**

## 命令速查

| 命令 | 作用 |
|---|---|
| `tar -tvf 包.tar` | 看 `.tar` 内容（不解压） |
| `tar -tzvf 包.tar.gz` | 看 `.tar.gz` 内容（不解压） |
| `unzip -l 包.zip` | 看 `.zip` 内容（不解压） |
| `tar -xzvf 包.tar.gz -C 目录` | 解压到指定目录（减少损失，非防御） |
| `tar -czf 包.tar.gz --transform 's\|A\|B\|' 文件` | **篡改包内路径（用于造实验样本）** |
| `ls -la` | 解压前后对比，确认有没有多余文件 |
